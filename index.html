📑 Abstract

Academic Specification

Allocating examination seating for universities handling hundreds or thousands of students is a complex combinatorial problem that is traditionally prone to human error, administrative bottlenecks, and academic integrity risks. This project presents an automated, AI-driven Intelligent University Exam Hall Seating Allocator modeled as a Constraint Satisfaction Problem (CSP) and solved via Backtracking Search with Domain Pruning and Variable Ordering.

The system ingests student rosters, prioritizes hard accessibility constraints (ADA compliance), and enforces an anti-cheating isolation rule by preventing students of the same degree section or the same course paper from occupying orthogonally adjacent seats (|Δrow| + |Δcol| = 1). Designed and implemented in Python and deployed as a responsive web platform, the system processes and validates a multi-room seating allocation for 50 students across three examination halls, demonstrating correct, repeatable results and strict adherence to institutional academic standards.

1. Introduction

Problem & Objectives

The purpose of this project proposal document is to establish the design, architectural framework, and implementation blueprint for an automated exam hall seating allocation system. In modern universities, academic scheduling and invigilation planning require careful attention to physical constraints, institutional capacities, and academic honesty. Traditional manual seating arrangements are tedious, error-prone, and inefficient, and they often fail to detect section clusters or students sitting the same paper side by side. Furthermore, failing to accommodate students with physical impairments violates accessibility expectations.

This software addresses the real-world problem of examination hall cheating vulnerabilities and accessibility oversights by replacing manual allocation with an automated AI approach. By formalizing seating arrangement as a constraint satisfaction problem, the system guarantees that no two students taking the same course paper, or belonging to the same degree section, sit directly next to each other (left, right, front or back). Through this development, key technical skills are acquired, including algorithmic problem modeling, state-space search, backtracking recursion, constraint checking, and structured data handling using Python and modern full-stack web technologies.

2. Proposed System & Mathematical Formulation

CSP ⟨X, D, C⟩

The proposed system addresses the complexities of institutional examination seating by applying core artificial intelligence and search techniques covered in coursework. Instead of relying on manual sorting, the application models the exam hall layout as a formal Constraint Satisfaction Problem (CSP):

Variables (X): 50 Examination Candidates {X₁, X₂, ..., X₅₀}, with ADA candidates prioritized first.
Domains (D): 75 Physical Desks across Hall A (25), Hall B (25), and Hall C (25). Each seat defined as {Hall_X-RrCc, row, col, ada_compliant}.
Hard Constraint (C₁): ADA Accessibility → If student.ada_needed = True ⇒ seat.ada_compliant = True (Ground floor, Row 1 of accessible hall).
Anti-Cheating Soft/Hard Constraint (C₂): Orthogonal Adjacency Isolation → In the same room, for any two desks where |r₁ - r₂| + |c₁ - c₂| = 1:
• student_A.section ≠ student_B.section
• student_A.course_code ≠ student_B.course_code
Uniqueness Constraint (C₃): Each candidate allocated to exactly one unique physical seat without collision.

The backtracking engine recursively searches the state space: assign candidate → verify is_safe() → recurse → if dead-end reached, undo assignment and explore next branch.

4. Scope & System Boundaries

Project Bounds

The scope of this project covers the design, implementation, and evaluation of an automated Python and Web-based Constraint Satisfaction Problem solver tailored to university examination seating. The system takes a student roster containing student identifiers, names, degree sections, course codes, and ADA accommodation flags. It manages multiple halls with configurable row and column dimensions, runs a backtracking search with strict orthogonal adjacency separation, and prints a formatted allocation report.

Boundaries: The system handles spatial isolation, room capacities, and accessibility rules. It does not perform optical character recognition (OCR) student card scanning, real-time biometric attendance tracking, or faculty invigilation duty rostering. These external administrative modules fall outside the current project scope.

6. System Limitations / Constraints

Technical Boundaries
  • The system assumes static room grid layouts with uniform row and column dimensions per examination hall.
  • ADA seats are designated to row 1 of accessible halls. Hall A row 1 has 5 seats, which accommodates up to 5 ADA students in the baseline scenario.
  • Backtracking search without heuristics can experience exponential runtime in dense, over-constrained cases where seats equal students. Providing 75 seats for 50 candidates keeps runtime optimal (<5ms).
